# 技術CVプロダクト 要件ドラフト

## 1. 目的
- Webエンジニアの技術的な履歴（CV）を、継続的に更新・公開できるようにする。
- 入力はローカル環境で完結させる。
- 公開は GitHub Pages で行う。

## 2. ゴール（MVP）
- CVデータをローカルで登録・更新できる。
- 登録データを軽量DB（候補: SQLite）に永続化できる。
- DBのデータから静的HTMLを生成できる。
- 生成物を `docs/` 配下に出力し、GitHub Pages で公開できる。

## 3. 想定ユーザー
- 主体: 自分（運用者1名）
- 将来的には複数プロフィールの管理も視野に入れるが、MVPは単一ユーザー運用を優先する。

## 4. 機能要件
1. CVデータ登録
- 氏名、肩書き、概要、職務経歴、スキル、プロジェクト、外部リンクを保持できる。
- ローカルで編集できる（CLI/ファイル編集/UIは要相談）。

2. 永続化
- ローカルDBに保存できる。
- 再起動後もデータが保持される。

3. HTML生成
- 保存済みデータから公開用HTMLを生成できる。
- GitHub Pages向けに `docs/` へ出力できる。

4. 公開
- `docs/index.html` をエントリーポイントとして公開できる。
- 公開URLとローカルデータは分離される（ローカルDBは公開物に含めない）。

## 5. 非機能要件
- セットアップが簡単であること（新規環境でも短時間で再現可能）。
- 手動運用でも負担が小さいこと（更新フローが明確）。
- 将来の拡張が可能であること（テンプレート変更、複数ページ化など）。

## 6. 運用要件（暫定）
1. ローカルでCV更新
2. HTML生成
3. `docs/` をGitへコミット
4. GitHub Pagesへ反映

## 7. 検討事項（次回相談）
- 入力方式: `JSON/YAML編集` vs `CLIフォーム` vs `ローカルWeb UI`
- 実装言語: `Go` / `TypeScript(Node)` / `Python`
- HTML生成方式: テンプレートエンジン採用有無
- データモデル: 単一プロフィール前提か、複数プロフィール前提か
- デプロイ導線: 手動生成のみか、GitHub Actionsも使うか
- デザイン方針: シンプル優先か、ブランディング重視か

## 8. 受け入れ条件（MVP）
- ローカルで1件以上のCVを登録できる。
- そのデータがDBに保存される。
- 生成コマンド1回で `docs/index.html` が出力される。
- GitHub Pages上で公開ページを閲覧できる。
